# ADR-004: Idempotencia Operacional y Resiliencia Transaccional

## Estado

Aceptado

## Contexto

El proyecto está diseñado para ser ejecutado repetidamente durante
pruebas, demostraciones y validaciones técnicas.

Las ejecuciones reiteradas no deben generar duplicados, corrupción de
datos ni inconsistencias en claves primarias.

## Decisión

Todos los scripts operativos incorporarán principios de:

- Idempotencia.
- Reinicialización controlada.
- Manejo transaccional.
- Recuperación automática ante errores.

Se implementan:

- DROP IF EXISTS
- TRUNCATE TABLE
- DBCC CHECKIDENT
- TRY...CATCH
- ROLLBACK
- COMMIT

## Consecuencias

### Positivas

- Repetibilidad absoluta.
- Entornos reproducibles.
- Mayor confiabilidad para pruebas.

### Negativas

- Mayor complejidad inicial de desarrollo.
- Necesidad de documentación adicional.
- Incremento marginal del tiempo de ejecución por validaciones adicionales.
