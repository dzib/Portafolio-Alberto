# ADR-002: Despliegue e Infraestructura Contenerizada con Docker Compose

* **Estado:** Aceptado
* **Contexto:** Para evitar discrepancias de entornos locales de
  desarrollo (incompatibilidades de versiones de Python como Python
  3.13/3.14 frente a las restricciones de Airflow) y garantizar la
  portabilidad del portafolio (*one-click deployment*), es necesario
  aislar los servicios.
* **Decisión:** Implementar un despliegue contenerizado mediante
  **Docker Compose**, integrando un motor de base de datos **PostgreSQL
  13** para los metadatos, un mecanismo automatizado de inicialización
  (`airflow-init`) y los servicios desacoplados de Webserver y Scheduler.
* **Consecuencias:**
  * **Positivas:** Asegura reproducibilidad absoluta e idéntica del
    entorno tanto en estaciones locales Windows/Linux como en servidores
    de nube, eliminando el "en mi máquina sí funciona".
  * **Negativas:** Demanda el uso activo de recursos de virtualización
    (Docker Desktop) durante el desarrollo local.
